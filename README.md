# cc-container-yard

管理箱位、堆叠关系和场内移动任务。

## 主要业务规则

- **堆位建模**：堆场由多个堆栈（`YardStack`）组成，每个堆栈有最大层数与最大总重量；
  集装箱（`Container`）有全局唯一箱号、重量和当前位置（所属堆栈 + 层号），
  同一堆栈内层号唯一（数据库唯一约束 `uk_container_stack_tier`）。
- **可移动性**：只有位于栈顶的箱可以移动；目标堆栈加入该箱后不能超过层数或重量上限；
  不允许移动到箱当前所在的堆栈。
- **计划校验**：移箱计划由按顺序执行的步骤组成（箱号 + 目标栈）。提交计划时在内存中
  完整模拟全部步骤：逐步校验源箱处于（模拟后的）栈顶、目标堆栈存在且容量足够，
  同一箱在步骤间的位置保持连续。任一步失败则整份计划不保存（HTTP 422）。
- **版本快照**：计划保存时记录所有涉及堆栈（源栈与目标栈）的 `@Version` 版本快照。
- **安全执行**：执行在单一事务中完成——先对计划行加悲观写锁（保证重复执行幂等），
  再按堆栈编码排序对相关堆栈加悲观写锁（避免死锁），逐一比对版本快照；
  任一堆栈版本已变化则整份计划标记为 `STALE_REJECTED` 并拒绝（HTTP 409），
  不会执行部分步骤。校验通过后重放全部步骤，一次性更新位置、重量、层级与版本，
  并写入不可变的移动事件（`MoveEvent`）。
- **幂等与并发**：重复执行同一计划返回原结果，不产生重复事件；两个计划并发修改
  共享堆栈时，数据库行锁 + 版本比对保证最多一个基于同一版本成功，另一个按陈旧拒绝。
  并发控制依赖 JPA 悲观锁与乐观版本（数据库层面），不依赖进程内锁。

## API 概览

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/yard/layout` | 堆场布局（各堆栈容量、当前重量/层数、版本、箱列表） |
| POST | `/api/stacks` | 新建堆栈 `{code, maxTiers, maxWeight}` |
| POST | `/api/containers` | 箱入场 `{containerNo, weight, stackCode}`（放到栈顶） |
| POST | `/api/plans/simulate` | 模拟计划，返回逐步校验结果，不落库 |
| POST | `/api/plans` | 校验并保存计划（含版本快照），失败返回 422 |
| GET | `/api/plans/{id}` | 查询计划详情 |
| POST | `/api/plans/{id}/execute` | 执行计划；陈旧计划返回 409 |
| GET | `/api/events?planId=` | 查询移动事件（可按计划过滤） |

## 开发环境

- JDK 21
- Spring Boot 4.1.1
- Maven Wrapper 3.9.9
- H2

## 本地运行

启动服务：

    ./mvnw spring-boot:run

运行测试：

    ./mvnw clean test
