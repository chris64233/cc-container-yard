# cc-container-yard

管理箱位、堆叠关系和场内移动任务。

## 主要业务规则

- **堆位建模**：堆场由多个堆栈（`yard_stack`）组成，每个堆栈有最大层数和最大总重量；
  集装箱（`yard_container`）有唯一箱号、重量和当前位置（所属堆栈 + 层号），
  数据库对箱号、堆栈编码、`(堆栈, 层号)` 均建有唯一约束。
- **移动规则**：只有位于栈顶的集装箱可以移动；目标堆栈加入后不能超过最大层数或最大总重量；
  不允许原地移动（目标栈与源栈相同）。
- **计划校验**：移箱计划由按顺序执行的多个步骤组成。提交时在内存中完整模拟全部步骤
  （`YardSimulator`，不触碰实体状态），逐步校验源箱在栈顶、目标堆栈有效、
  同一集装箱多次移动时位置与上一步结果连续；任一步失败则整份计划不保存。
  计划保存时记录所有涉及堆栈的版本快照（`plan_stack_snapshot`）。
- **安全执行**：执行在单一事务中重放全部步骤。执行前逐一堆栈比对版本快照，
  任一相关堆栈版本已变化则整份计划标记为 `STALE` 并拒绝，不执行部分步骤；
  执行成功则一次性更新所有位置、重量、层数和版本，并写入不可变移动事件（`move_event`，
  字段均 `updatable = false`）。
- **并发与幂等**：堆栈使用 JPA `@Version` 乐观锁，计划行使用悲观写锁（`SELECT ... FOR UPDATE`），
  不依赖进程内锁；两个计划并发修改共享堆栈时最多一个基于同一版本成功，
  另一个在提交时因版本冲突失败（HTTP 409）。重复执行同一计划返回首次执行的原结果，
  不会重复写入事件。

## API 概览

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/api/stacks` | 创建堆栈（编码、最大层数、最大总重量） |
| POST | `/api/containers` | 登记集装箱（放入指定堆栈顶部，校验层数与重量） |
| GET | `/api/layout` | 查询堆场布局（各堆栈箱量、重量、版本） |
| POST | `/api/plans` | 提交移箱计划（模拟校验通过后保存，返回模拟结果与版本快照） |
| GET | `/api/plans/{id}` | 查询计划详情与模拟结果 |
| POST | `/api/plans/{id}/execute` | 执行计划（幂等；版本过期返回 `STALE`） |
| GET | `/api/plans/{id}/events` | 查询计划产生的移动事件 |

## 开发环境

- JDK 21
- Spring Boot 4.1.1
- Maven Wrapper 3.9.9
- H2

## 本地运行

启动服务：

    ./mvnw spring-boot:run

运行测试：

    ./mvnw clean test
