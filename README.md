# cc-container-yard

管理箱位、堆叠关系和场内移动任务。

## 主要业务规则

- **堆位建模**：堆场由多个堆栈（`YardStack`）组成，每个堆栈有最大层数与最大总重量；
  集装箱（`Container`）有全局唯一箱号、重量和当前位置（所属堆栈 + 层号），
  同一堆栈内层号唯一（数据库唯一约束 `uk_container_stack_tier`）。
- **可移动性**：只有位于栈顶的箱可以移动；目标堆栈加入该箱后不能超过层数或重量上限；
  不允许移动到箱当前所在的堆栈。
- **计划校验**：移箱计划由按顺序执行的步骤组成（箱号 + 目标栈）。提交计划时在内存中
  完整模拟全部步骤：逐步校验源箱处于（模拟后的）栈顶、目标堆栈存在且容量足够，
  同一箱在步骤间的位置保持连续。任一步失败则整份计划不保存（HTTP 422）。
- **版本快照**：计划保存时记录所有涉及堆栈（源栈与目标栈）的 `@Version` 版本快照。
- **安全执行**：执行在单一事务中完成——先对计划行加悲观写锁（保证重复执行幂等），
  再按堆栈编码排序对相关堆栈加悲观写锁（避免死锁），逐一比对版本快照；
  任一堆栈版本已变化则整份计划标记为 `STALE_REJECTED` 并拒绝（HTTP 409），
  不会执行部分步骤。校验通过后重放全部步骤，一次性更新位置、重量、层级与版本，
  并写入不可变的移动事件（`MoveEvent`）。
- **幂等与并发**：重复执行同一计划返回原结果，不产生重复事件；两个计划并发修改
  共享堆栈时，数据库行锁 + 版本比对保证最多一个基于同一版本成功，另一个按陈旧拒绝。
  并发控制依赖 JPA 悲观锁与乐观版本（数据库层面），不依赖进程内锁。

## 进出场预约

闸口时段、堆位预留与前置移箱计划作为一个整体协调：预约即批准，任一资源或步骤
不成立时整笔预约失败回滚，不会留下半占用的资源。

- **闸口时间窗**：`GateWindow` 按时间窗配置可处理车辆数（`capacity`）。预约时对该行
  加悲观写锁并递增 `bookedCount`，并发预约不会突破容量；取消时释放。
- **预约声明**：箱号、方向（`IN`/`OUT`）、车辆、时间窗、目标堆栈；进场还需声明箱重。
  一个箱同一时间只能存在一笔有效预约——`appointment.active_container_key` 唯一约束
  在数据库层面保证（到场或取消后置空，该箱可再次预约）。
- **进场预约**：批准时同时预留闸口能力和目标堆位（`SlotReservation`，层号 =
  当前层数 + 该栈已生效预留数 + 1），并校验堆栈层数（高度）与重量上限（累计现有
  箱重与已预留箱重）。`active_slot_key`（堆栈#层号）唯一约束防止重复占用或孤立堆位。
- **出场预约**：批准时按当前堆叠关系生成前置移箱计划——压在目标箱上方的箱自上而下
  依次移到其他有空余层数与重量的堆栈（空余容量扣除已生效的进场预留）。任一箱无处
  可移则整笔预约失败。计划涉及的堆栈（源栈 + 移箱目标栈）记录版本快照，
  计划版本 `planVersion` 从 1 开始。
- **到场确认**：校验预约版本（请求携带 `planVersion`，不一致返回 409）、时间窗
  （当前时间必须落在窗口内）和箱的实际位置（进场箱不得已在场内，出场箱必须仍在
  声明的堆栈）。若快照堆栈版本已变化或既有移箱目标容量被预留占满，旧出场计划
  不得执行：系统按当前布局重新规划（`planVersion` 递增）后确认；重新规划失败
  （箱已离场、箱不在声明堆栈、无可用堆位）则保留原预约并置 `manualReview`，
  返回 409 等待人工处理，资源不释放。
- **业务号幂等**：预约（`appointmentNo`）、到场（`arrivalNo`）、取消（`cancelNo`）
  各自幂等——相同业务号重放返回原结果，不同业务号重复操作返回 409。
  取消只能在 `BOOKED` 状态发生一次，状态机 + 行锁保证闸口容量与堆位只释放一次。

## API 概览（预约）

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/api/gate/windows` | 配置闸口时间窗 `{startAt, endAt, capacity}` |
| GET | `/api/gate/schedule` | 闸口日程（各时间窗容量、已约、剩余） |
| POST | `/api/appointments` | 预约（声明箱号/方向/车辆/时间窗/目标堆栈/箱重）；相同 `appointmentNo` 重放返回原预约（200），新预约返回 201 |
| GET | `/api/appointments/{appointmentNo}` | 预约详情（状态、计划版本、预留堆位、前置移箱步骤、布局快照） |
| GET | `/api/appointments/{appointmentNo}/pre-moves` | 前置移箱步骤列表 |
| POST | `/api/appointments/{appointmentNo}/arrival` | 到场确认 `{arrivalNo, planVersion}`；`outcome` 为 `CONFIRMED`/`REPLANNED`（200）或 `MANUAL_REVIEW`（409） |
| POST | `/api/appointments/{appointmentNo}/cancel` | 取消预约 `{cancelNo}`，释放闸口容量与堆位预留 |
| GET | `/api/yard/occupancy` | 资源占用（各堆栈当前/已预留/可用的层数与重量及预留明细） |

## API 概览（堆场与移箱计划）

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/yard/layout` | 堆场布局（各堆栈容量、当前重量/层数、版本、箱列表） |
| POST | `/api/stacks` | 新建堆栈 `{code, maxTiers, maxWeight}` |
| POST | `/api/containers` | 箱入场 `{containerNo, weight, stackCode}`（放到栈顶） |
| POST | `/api/plans/simulate` | 模拟计划，返回逐步校验结果，不落库 |
| POST | `/api/plans` | 校验并保存计划（含版本快照），失败返回 422 |
| GET | `/api/plans/{id}` | 查询计划详情 |
| POST | `/api/plans/{id}/execute` | 执行计划；陈旧计划返回 409 |
| GET | `/api/events?planId=` | 查询移动事件（可按计划过滤） |

## 开发环境

- JDK 21
- Spring Boot 4.1.1
- Maven Wrapper 3.9.9
- H2

## 本地运行

启动服务：

    ./mvnw spring-boot:run

运行测试：

    ./mvnw clean test
